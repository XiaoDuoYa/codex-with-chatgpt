# Staging Manifest v2

`submit_plan` consumes a staged project. It does not stage source files itself. A compatible staging producer must publish this exact tree under the connected workspace:

```text
<workspace>/<project>/
  CONTEXT-MANIFEST.json
  <approved files>
```

The workspace root, project directory, and nested directories must be owned by the current user and inaccessible to group or other users on POSIX systems. Symlinks and non-regular files are rejected.

## Manifest schema

`CONTEXT-MANIFEST.json` is UTF-8 JSON with no duplicate object members and exactly these top-level fields:

```json
{
  "schema": 2,
  "project": "exact-project-directory-name",
  "classification": "synthetic",
  "files": [
    {
      "path": "PROJECT.md",
      "bytes": 29,
      "sha256": "858be65bc3f16984d260c81db17544e423db9d8670a1fe6135768d982dc9fdb6"
    }
  ],
  "limits": {
    "max_file_bytes": 1000000,
    "max_total_bytes": 10000000
  },
  "approval_digest": "50cf047d1b8563455f24d4dfa26a39a9e5c702fc1cba9ff3a92253c5c2b580f7"
}
```

Allowed classifications are `public`, `synthetic`, and `sanitized`. The file list must be non-empty, contain at most 500 unique safe relative paths, and exactly match the staged regular-file set except for `CONTEXT-MANIFEST.json`.

Paths must follow the C2C staging allowlist. Supported suffixes are `.css`, `.csv`, `.go`, `.graphql`, `.html`, `.java`, `.js`, `.json`, `.jsx`, `.md`, `.mjs`, `.py`, `.rs`, `.sh`, `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.yaml`, and `.yml`. Supported extensionless names are `Dockerfile`, `Makefile`, `README`, and `LICENSE`. Sensitive names and components such as `.env`, `.git`, credentials, secrets, passwords, private keys, and access or refresh tokens are rejected.

## File hashes

For each approved file:

- `bytes` is the exact byte length, at most 1,000,000;
- `sha256` is the lowercase SHA-256 of the exact file bytes;
- the sum of `bytes` is at most 10,000,000.
- every file is valid UTF-8 text without NUL bytes or secret-like content.

## Approval digest

Build the release payload by removing only `approval_digest`:

```json
{
  "schema": 2,
  "project": "...",
  "classification": "...",
  "files": [],
  "limits": {
    "max_file_bytes": 1000000,
    "max_total_bytes": 10000000
  }
}
```

Serialize it with Python-compatible canonical JSON:

```python
(json.dumps(payload, sort_keys=True, separators=(",", ":")) + "\n").encode("utf-8")
```

`approval_digest` is the lowercase SHA-256 of those bytes. Array order is preserved. Producers should sort `files` by relative path before calculating the digest.

`tests/fixtures/manifest-v2-golden/` was generated by the C2C staging producer and is checked by the plan-inbox test suite. Its approval digest is:

